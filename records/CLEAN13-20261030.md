## 4. The r15 hw/car + hw/trashbin rows are superseded — evidence

r15-vs-fresh (same recipe, same node, same A *structure*):

Why this is a *data-window* effect, not module-A randomness:

1. **A structure is identical across all historical batches.** Fresh-A COLMAP registers
   `64 / 79 / 70 / 75` images for billboard/basketball/car/trashbin at resolutions
   `[768,512] / [768,512] / [768,576] / [768,576]` — exactly the registered counts and resolutions
   of both earlier batches (r15 `07:16Z` and `cand ~18:24Z`, per P0/task-4). So the outlier is not
   a registration/camera-count difference.
2. **Current hw COLMAP is reproducible to ~0.02–0.03°.** Two independent fresh A runs
   (car, trashbin) on the exact scored artifacts:
   - `split.json` **byte-identical** (car `f29a052c2714…`, trashbin `4d618e368f24…`; identical
     image list, train/test split, 16 context indices, resolution, registered count 70/70 and 75/75);
   - gauge-corrected per-image pose residual **mean 0.0218° / median 0.0203° / max 0.0434°** (car,
     70 common images) and **0.0276° / 0.0252° / 0.1125°** (trashbin, 75 common images);
   - camera-centre RMS 0.0035 (car) / 0.0084 (trashbin) COLMAP units; global gauge rotation
     0.573° / 2.091° (a frame rotation, harmless — scene+poses rotate together);
   - PINHOLE intrinsics agree to 0.044/0.057 % (fx/fy, car) and 0.027/0.049 % (trashbin), cx/cy identical.
   `images.txt`/`cameras.txt` sha256 differ only because of that gauge+BA micro-noise;
   the artifact that drives train/test/context (split.json) is byte-identical.
   **Independently recomputed by the Lead with a gauge-invariant relative-rotation metric; agrees
   to within the reported spread** (car median 0.0213°, p90 0.054°, max 0.0723°; trashbin median
   0.0381°, p90 0.0605°, max 0.1465°; camera-distance ratio 1.0000±0.002; identical split.json).
3. **Input data identity:** H1 `/workspace/organizer-assets/datasets/hw/{car,trashbin}/images`
   md5-match the Mac canonical copy (sampled 3 files each; full name+size inventory hash-matched) —
   verified by the team before this run (P0/task-4). The current raw data is the clean copy; the r15
   run at 07:16 UTC sat inside the loss/re-upload window.
4. **Independent second draw:** the N1/E2 `cand`-batch draw gives hw/car 47.95 and hw/trashbin 65.94
   — i.e. clean13 (48.54 / 64.98) reproduces the *other* batch within ±0.6, not r15's 67.5 / 25.4.
5. The two unaffected hw scenes reproduce r15 within +0.29 / +0.07 (delivery) and +0.25 / −0.60
   (baseline), i.e. normal repeat noise.

**Conclusion:** the r15 `hw/car`-delivery `67.525` and `hw/trashbin`-delivery `25.413` rows (and
their baselines) are artifacts of the 07:16Z hw data window and are **superseded**. The old paired
headline `41.371 → 49.599` is therefore not defensible; use `42.323 → 51.153 (+8.830)`.

## 8. Caveats / anomalies (nothing re-run)

- **Hybrid A** (§1): 9 reused event-free work dirs + 4 fresh hw; the table marks every row.
- **No timing outliers, no re-runs.** B ∈ [21.84, 36.49] s; every run was the first clean attempt
  (all `attempt=1`, rc=0). The one `HALT` line in `pipeline.log` (16:48:41Z) is a **false positive
  from a buggy v4 contamination checker** (inverted return polarity + conda-run descendant
  detection): no foreign job existed; the halted scene's partial dir was deleted and the loop
  restarted at 16:50:19Z with a path-allow-list detector (`foreign_procs()` flags only
  research/competition/colmap jobs whose cmdline does NOT contain `outputs/clean13-20261030`),
  a halt-time `kill_tree()` so no orphan can survive, a startup self-test (logged `[]`), and
  resume-skip. **No result from the halted attempt is counted.** `pipeline.log` contains exactly
  one HALT line (the false positive above) and no HALT after the 16:50:19Z restart.
- **`hwA-summary.json._determinism` is stale/superseded**: it was generated before the repeat
  output dirs were normalized and compares empty fields (it reports everything as unequal).
  The authoritative determinism evidence is `determinism.json` (§4). Use that, not the embedded block.
- **CPU-contention sensitivity:** module-B seconds depend on CPU quiet (a-poses measured
  +40% B under COLMAP load). This run gates on loadavg+GPU+foreign processes before every stage;
  the A stage completed before any GPU stage, and E1's N1 sweep had run concurrently on another
  node (irrelevant to B). B values here are same-node serial measurements and should be compared
  as such, not mixed with concurrent-lane numbers.
- **Repeat noise:** same-config delivery repeats on the 9 reused scenes reproduce r15 within ±0.31
  points, and the E2 cross-draw differs by ≤1.23 per scene; single-point differences <1 point are
  noise (consistent with task-2's measured σ≈0.22).
- The r15 baseline arms for the 9 non-hw scenes are reused because their A is event-free and
  identical; if a fully fresh-baseline re-measurement of all 13 is ever wanted it costs another
  ~15 min GPU, but it is not needed for the paired headline (hw is the only contaminated group).
