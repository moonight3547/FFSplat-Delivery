## 1. Exact command

```bash
python3 scripts/run_exact13_gate.py \
  --out-root outputs/final13-d3500-v200-cache-20261030 \
  --recipe bigd3500 --vgg-tail 200 --scene-cache \
  --tau 0.48 --keep 0.6
```
Per case the runner: quiet-gate → deterministic M1 `research.prune_gate`
(8 fixed unshuffled train views, `tau=0.48`, `keep=0.6`) → build
`<work>/scene_tensor_cache` if absent (A-side data residency) → delivery module B
with `--recipe bigd3500` (`--densify-from 500 --densify-until 3500
--densify-interval 100 --grad-abs-thresh 0.0008`), `--vgg-tail 200`
(`--lpips-weight 0.1 --lpips-scale 1.0 --lpips-start 4801 --lpips-end 5000`),
`--scene-cache <cache>`, `--realloc-frac 0.15 --realloc-at 1250`,
`--mid-prune-at 1250 --mid-prune-keep <gate>`, S=5000, LR/loss/seed as the
delivery recipe (`--seed 20261015`, cache from `<work>/image_cache`).

`research.prune_gate` at `3b408ea` uses `Scene(..., shuffle=False)` +
`fixed_view_indices` (`camera_order="unshuffled"`), so the 8 gate views are

`cells/<tag>/gate.json` inside the run root.

## 6. Caveats

1. **One host, one repeat.** This is a single serial measurement on H1 (quiet-gate
   enforced per case; `/proc/loadavg` container value, not `os.getloadavg()` which
   reports the physical host on this pod). Expect ~±0.5 total run-to-run noise; the
   N1 cells above bracket that.
2. **Gate threshold margin:** bicycle's train-LPIPS 0.4987 is only 0.019 above
   `tau=0.48`; a seed/render perturbation could flip the gate on bicycle. It is the
   only case anywhere near the threshold (next highest 0.4142), so the aggregate is
   insensitive to a flip (max exposure ≈ the bicycle keep delta).
3. `hw-billboard` shows the smallest gain (+1.193); its LPIPS (0.1243) is far below
   the cliff, so most of its gain is the D3500 densify/recipe change, not VGG.
4. The paused separate exact-13 gatefix run (7 rows) is untouched and unrelated to
   this fresh root; no rows are shared or mixed with D2500 or old VGG matrices.
5. Disk after the run: **62 GB free** of 200 GB (all run artifacts kept; no
   cleanup was triggered — the <20 GB rule never bound).
