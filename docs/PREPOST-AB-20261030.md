# 报告思路 → 模块 A / 模块 B 分派与可行性（2026-10-30）

把 [`FeedForward_3DGS_PrePost_Report_20261029.md`](../../FeedForward_3DGS_PrePost_Report_20261029.md)（下称 **R**，§ 指其章节）里的条目，逐条判定为「模块 A 可用 / 模块 B 可用 / 跨 A-B / 出局 / 观察」，并落到本仓库的现有入口上。

本文只做分派与可行性判定，**不新增 GPU 实验**。标 `[实测]` 的数字全部来自 `records/` 或 [`docs/RESEARCH-20261030.md`](RESEARCH-20261030.md)；标 `[报告自述]` 的是 R 中作者自报、我方未复现的；标 `[未验证]` 的是有入口但没有跑过、或跑过但无归档 JSON。

管线的固定形状来自 [`ProblemDesc.md`](../ProblemDesc.md)：图像+相机 → **A**（位姿、预处理、16 视角选择）→ **ReSplat**（冻结，`num_refine=2`）→ **B**（高斯后优化）→ PLY / PNG / 报告。

## 0. 分派规则（先定规则，再谈条目）

| # | 规则 | 后果 |
|---|---|---|
| 1 | **落点**：改变「ReSplat 看什么、喂什么」→ **A**；改变「ReSplat 吐出来的高斯集合，或它的优化过程」→ **B**。 | 同一条报告条目经常要拆成两半 |
| 2 | **可移植性**：需要训练新网络、改 ReSplat、或用新数据集 → **出局**，只保留它的「推理期等价物」或「设计教训」。 | R 的 §3.1/§3.3/§4 里绝大多数增益都是在训练期支付的；R 开头的 caveat 也承认「backbone-agnostic ≠ 权重可用」 |
| 3 | **交付物**：最终交付是可加载 PLY + 官方渲染 PNG。只在像素层生效的增强不算 asset 改进。 | 直接排除 R §4 的两个扩散路线、R §5 的 ViewSplat 神经资产 |
| 4 | **时间**：B 侧秒数进 TIME 分子；A 侧秒数只在 E2E 口径下计入，而该口径**尚未钉死**（`official_score_100=null`）。 | A 侧「多跑一次前馈/多一次预处理」的想法在 E2E 口径下直接扣分 |
| 5 | **禁止项**：不用 test RGB 指导 A/B，不做逐场景超参。 | 排除「用 held-out 视角反选 context」「按场景开不同档致密」这类做法 |

R 的 §1（交付物四分类）和 §7（基准协议）不提供方法，但是**判定别的条目的尺子**：前者已折进 §0 规则 3，后者的缺口在 §7 单列。

两条推论直接决定后面的取舍：

1. R 建议的「先做输入选择、再做短程精化」（R §8）与我们实测一致，但**权重不同**：我们这边 A 侧的初始化值 28 分，B 侧内部只差 2 分。所以 A 侧条目应排在 B 侧前面。
2. R 的 §3 每一节都能给出「更好的高斯资产」，但那是**有训练预算**的前提下；在冻结 ReSplat 的约束下，B 侧能拿的只是「同样质量更少秒数」和「B=0 就能拿的免费初始化整理」。

### A1 — 覆盖度 + 连通性的 16 视角选择（R §2.1 主投射）
- **报告提供的机制**：把每视角点图离散进 3D cell，用 Morton 序序列化后贪心选「新增覆盖」最多的视角；这正是对「均匀抽帧」的替代。
- **我们已有的**：`research/select_views.py` 的 `coverage` 策略（相机中心 bbox 体素化，`1/sqrt(freq)` 加权，中心 50%×50% 投影，贪心）与 `fps`（maximin 间距）；`uniform` 是赛方基线。16 个视角、只从 `split.json["train"]` 取、不改网络。
- **报告额外给的两条硬约束**（我们还没实现）：
  1. **重叠连通性**：贪心最大化覆盖可能选出互不连通的观察集（R 明确说「最大化覆盖 ≠ 允许不连通」）。→ 加一条约束：新视角必须与已选集合至少有 k 个共享可见体素（或与已选视角的最小基线距离 < 阈值），否则跳过。
  2. **复用 depth/pose prepass 要计成本**：R 提醒「几何预测有成本，声称选图加速了整条管线时必须把它算进去」。我们没有 depth prepass，选图是纯 CPU，这条对我们有利但要在报告里写明。
- **现状**：历史 `ranked16` 在三例上**没有改变**选中的 context（SUMMARY §5.1/5.6）；`fps`/`coverage` 已在代码里但**没有 GPU 结果** `[未验证]`。所以这条不是「已证伪」，是「没真正测过」。
- **最小验证**：三例各跑 uniform / fps / coverage（可再加 connectivity 版），只测 B=0 初始化质量 + 一次 4k 步接续。成本 ≈ 3 例 × 4 策略 × 一次 ReSplat 推理。
- **判死**：B=0 三例均值 < +0.5。

### A2 — 选图打分融合锐度/曝光/重叠（R §2.1 的 proposed adaptation + §2.3 的模糊/曝光项）
- **做法**：对每个候选训练视角算 Laplacian 方差（模糊）、曝光直方图离群度、与已选集的重叠率，作为 `coverage` 权重的乘子或硬剔除项；**数量固定 16，输出仍按 train 序排序**（保持 R 与本地 `context[8]` pivot 约定）。
- **为什么值得**：R §2.3 明确把「运动模糊、曝光变化」列为影响上游监督的工程因素；hw/billboard 是 AR 采集，模糊/滚动快门概率高，而它正好是质量墙。
- **约束**：不能看 test RGB；不能改变 COLMAP 阶段（赛方 A 可能在划分前对全部图做 COLMAP）。
- **判死**：同 A1。

### A3 — hw 类位姿/几何质量修复（R §2.2 的 A 半）
- **报告提供的判据**：先区分**全局相似/gauge 失配**和**局部深度畸变**；Sim(3) 对齐修不了非均匀几何误差。改坐标时必须同时变换高斯均值、协方差、相机、以及方向性外观约定（见本文 §5 的陷阱 1）。
- **我们的现场**：`module_a/preprocess.py` 里 hw 的 `frames_info.txt` AR 位姿「几何上无效」（旋转对得上、位置过不了任何刚体对齐检验），所以赛方是**从零跑 COLMAP**；hw 的 B=0 只剩 3.81 分、最好有效质量 34/80。
- **可尝试**：① 重投影一致性筛查（每帧 reprojection error / 特征内点率）剔除或降权坏帧；② COLMAP BA 精化参数（更多内点、开 `--refine_intrinsics` 之类）后重跑；③ 检查内参畸变模型与 resize 后的缩放；④ 用深度一致性（多视角三角化）找局部畸变区域。
- **不做**：不用 test RGB 拟合相机；不做完整 pose TTO（那是 VoxelTTO 的路，成本不允许）。
- **B 侧的替代路线（已有实现、未跑）**：`research/pose_refine.py` 在 B 训练末端只优化每视角的**世界空间平移**（旋转/内参冻结、位移夹紧、默认关闭），`research/depth_reg.py --pose-lr` 打开。它只吃训练视角的光度 + 深度监督、不碰 test RGB，所以规则上可行；但本质是「在 B 里改相机」，报告里必须显式说明这条 A/B 边界。
- **这条路线的技术陷阱（必须先想清楚，否则会把 A3 的账记到 B4 头上）**：只动训练视角的相机、测试相机仍用原 COLMAP 位姿时，B 拟合出的高斯落在一个与测试相机**不一致的 gauge** 里，held-out 渲染可能反而变差。可行的做法只有两种：把位移限制成极小的正则项（当「位姿不确定度」用，不是当 pose solver），或者确认出题方允许在 A 阶段重估位姿并让测试相机共用同一套参数化。
- **成本**：A 里最贵的；但也是唯一单场景有 20+ 分空间的地方（RESEARCH §7 结论）。
- **判死**：hw 的 B=0 质量不涨，或 COLMAP 精化让 A 耗时涨到 E2E 超预算。

### A4 — 预处理/坐标审计（R §2.3 检查表，零训练、低成本、必做）
- **清单**：内参随 resize/crop 的缩放断言；畸变约定；pose 手性（我们的 `images.txt` 是 world-to-camera，`camera_center=-Rᵀt`）；图像顺序与 `split.json` 顺序一致；横屏长边 ≤960 / 竖屏 ≤768、尺寸取 64 倍数、以及我们的竖屏补丁；A 侧各阶段耗时单独记（E2E 口径下 COLMAP 是直接扣分项）。
- **额外一条**：R §2.3 警告「任何生成式输入增强都要拿原图对照——编出来的纹理会变成跨视角不一致的证据」。我们已经默认不做输入增强，这条写成**明文否决**，避免以后有人加。
- **成本**：小时级、CPU；产出是断言与计时，而不是新方法。

### A5 — （本地思路，不是 R 的条目）多子集前馈集成
- `research/experiments/campaign_m.sh` 已经写好：同一 train split 抽两个 16 视角子集各跑一次 ReSplat，merge 两个 PLY 作为 B 的初始化。脚本注释里的卖点是「ReSplat 时间不进 B 预算 → 免费质量」。
- **与 R 的关系**：这条其实和 R §3.1 的「learned residual / 更好初始化」同源，但走的是「更多推理算力换初始化质量」。
- **风险（这正是 R §7 会拦下的）**：如果 TIME 分子是 **E2E**，多跑一次 ReSplat 直接进分子，A 侧可能一开始就吃掉预算。→ **先钉死 E2E/B-only 口径，再决定要不要跑 campaign M。** 现状：未跑、无归档。

### A 侧出局清单
- 生成式输入增强（R §2.3/§4 双重警告）。
- 改分辨率/上采样初始化（SR3R 要训练；赛方预处理固定）。
- InfiniSplat v2 的监督改动（训练）。
- Z-Order 的架构部分（稀疏注意力/冗余抑制）：我们只用它的选图机制。

### B1 — 初始化层的整理（R §3.2 剪枝半，免学习版；另见 `research/LIT.md` 的 InstantSplat「清点再拟合」）
- **可尝试**：不透明度重标定（`sharpen`，p→logit(2p)）；低不透明度/超大各向异性剪枝（`prune`）；跨视角冗余合并（`merge`/dedupe，对应 Saliency-Guided Merging 的免学习影子）；可选 `densify` 分裂以补容量。
- **剪枝判据可直接照抄** R §3.2 的 PointSplat（它有代码、无训练依赖）：把 opacity 与椭球体积各自 z-score 化后取双阈值，比我们现在手写的「opacity<0.01 或 scale>0.5」更稳，且天然跨场景（不需要逐场景调阈值）。
- **实测**：锐化初始化后接 FastGS = 60.03 vs 默认 59.02；纯预剪 floaters = 58.11；纯属性更新（大场景最强）= 58.37 `[实测]`。SUMMARY 归档里同一批实验的 uniform 最优是 51.735（不同机/不同机时，量级参考即可）。
- **成本**：分钟级，无训练；**这是 B 侧性价比最高的一层**，也是唯一在 B=0 就能打分验证的。
- **判死**：三例均值 < +0.5，或任一小场景掉分。
- **缺口**：`ply_ops` 现在有 inspect/prune/sharpen/densify，**没有 merge/层级合并**；报告的 Saliency 方法提示「合并是可学习的，但阈值化合并是免费的一半」，值得补。

### B2 — 固定拓扑 + attribute-only 短程优化，LR 日程匹配实际步数（R §3.3 ForeSplat 的免训练版 + R §6）
- **报告的逻辑**：ForeSplat 的 zero-step PSNR 反而低、+20 s 后反超 → 「好的初始化」和「好的优化起点」是两个目标；固定拓扑、只更新属性是被验证过的方向。
- **我们的实测**：默认 FastGS 位置 LR 日程按 30000 步衰减，跑 4k/8k 时 LR 仍停在 29%–47% 高位，settle 阶段根本没到；`--position-lr-max-steps=实际步数` 后，hw 8k 步质量 35.39 ≈ 长日程 12k 步的 35.49（RESEARCH §8）；三例统一 4k 步均值 58.24（RESEARCH §9，基线 49.63）`[未验证归档]`。**这是目前最大的单杠杆，但它还没进 JSON。**
- **可尝试的组合**：`--no-densify`（大场景强）/ `--densify-until` 限前 20%（小场景需要致密）/ 关不透明度重置（已测正收益，但 counter 反而略降）/ `--sh-up-every` 延迟 SH 阶数换步数。
- **统一超参难题**：结构操作的最优选择随场景规模变（DL3DV 288 训练视角关致密 +2.3，hw 56 / counter 210 需要致密 +1.5~3）。赛方禁止逐场景调参 → 只能写一条**按可观测场景属性（训练视角数/场景尺度）触发的统一规则**，并在报告里声明该规则是数据无关的。
- **判死**：三例均值 < +2。

### B3 — 锚定 / 信赖域（R §6 的 `∑λᵢ‖θᵢ−θᵢ⁰‖²` + R §3.3 Diff3R 的近端约束教训）
- **做法**：对 means 加衰减的 L2 pull、对 scale 做相对 init 的 clamp（前 50% 步）、对不同参数组用不同的锚定权重。
- **直觉**：hw 的失败模式是 floater 漂移（初始质量只有 3.81 分），把好的初始化保护起来比让它自由漂更划算；这也是 R §6 末尾「先用区域/属性级别的固定上界，再谈不确定性预测」的顺序。
- **成本**：需要给 `train_sweep.py` 加 loss hook，1 小时实现 + 5 分钟/例判死。
- **判死**：PSNR 低于对照，或均值 < +0.5。

### B4 — 几何项：深度 / 重投影（R §6 的 `λ_geom` + R §2.2 的 depth 精化）
- **可用信号**：ReSplat 自带的**预测深度头**（1/4 分辨率）——不是从 PLY 渲染出来的深度，所以比「渲染深度当约束」少一层同义反复；但它仍与初始化的几何同源，R §6 的警告「不可靠的预测深度不能当 GT」照样适用。
- **已落实现（工作区未提交、未跑）**：`research/export_resplat_depth.py` 把 16 个 context 视角的预测深度导成 sidecar，`research/depth_reg.py` 用**边缘感知**的深度项（Charbonnier + 梯度/边缘权重，`--depth-weight`/`--depth-every`/`--depth-start-frac`）监督 FastGS 渲染的 alpha 加权深度；`--pose-lr > 0` 时同时打开 A3 那条 translation-only 相机精化。默认全关。
- **可尝试的顺序**：先只开深度项（权重 0.05 量级、每 4 步、后 50% 步），确认它先把自己的 5–10% 步耗时赚回来；再考虑叠加 `--pose-lr`。
- **判死**：付完自己的时间成本后净增益 < +1（≈ 深度项自身开销 × 0.223 分/秒）。

### B5 — 结构操作当「买步数」的工具，不是质量工具（R §3.2 的 compaction 论点 + R §7 的「20× 高斯 ≠ 20× FPS」）
- **报告论点**：压缩改善的是**资产预算**（后续优化、存储、渲染），不必然提升保真度；并且渲染成本还取决于投影足迹、overdraw、排序、解码。
- **我们的实测反例**：放宽致密门槛 + 900K 上限（hw 8k）多了 32K 高斯，PSNR/SSIM/LPIPS 基本不动（22.729/0.7975/0.1573 vs 22.707/0.7978/0.1574），总分从 44.584 掉到 43.914 → 与 R 的论点一致 `[实测]`。
- **可做**：一次性预剪到 ~60% 再固定拓扑（把 FastGS 自己的剪枝提前，省掉致密阶段的时间）；关不透明度重置（已测）；不要指望加高斯加细节。
- **判死**：固定秒数下步数没涨 ≥15%。

### B6 — 生成式/扩散回流（R §4、P3）
- **裁决：本期不做。** 理由三条：①要训练或引入扩散先验与运行时依赖；②交付物是 PLY，图像增强不算 asset；③R 的部署规则要求「先报无增强结果」，而我们的评分表就是官方渲染 + VGG-LPIPS，没有位置再挂一个增强器。
- 若将来要做：必须先确认出题方允许，且按 R §4 的要求用置信/可见性掩码、保留原视角监督、插入新高斯要以几何证据为门槛。

### B 侧出局清单（R 原文里被误解风险最高的几条）
- **DeltaSplat 当插件**：报告自己写了「与 backbone 联合训练，非已验证的 ReSplat 插件」。
- **SplatFormer / SR3R / Fuse-and-Refine / 两个 merging 方法的 learned 部分**：都要训练。
- **ZipSplat**：换表示，不是后处理。
- **Diff3R / ForeSplat 本体**：训练期投入；我们只取其教训。
- **ViewSplat / VoxelTTO / FeCoSplat**：神经资产 / 框架级 / 传输层，与「静态 PLY 交付」不符。

## 5. 跨 A/B 的接口陷阱（R 里散落，但真能把实验做废）

1. **坐标变换要完整**（R §2.2 明说）：动坐标系时必须同转高斯协方差（Σ → RΣRᵀ）、SH 系数的方向约定、相机；只搬 means 会得到「中心对、朝向错」的各向异性高斯，视觉上像变糊/变亮，而且会被误判成优化器的锅。
2. **A 改 context 后要守恒的约定**：输出 context 必须按 train 序排序（本地 `research/select_views.py` 已保证），因为 ReSplat 用 `context[8]` 当 pivot；`split.json` 的 train/test 不能因为选图而变化。
3. **E2E vs B-only 分子未定**：R §7 的 total time 表把 decode/preparation/selection/prepass/optimization 全算进去，是 E2E 味；我们当前主报告 E2E、B-only 并列。**任何 A 侧「多跑一次前馈」的想法，在 E2E 口径下直接扣分**（campaign M 就是这类）。
4. **计时可比性**：R §7 要求同 GPU、同 view ID、同 crop、同分辨率。我们已经踩过：同机 7% 噪声、共享 vGPU 的墙钟不可用于 TIME 打分。任何 <2 分的差异不可采纳。

## 8. 建议顺序（按「每分钟换多少分」排）

1. **A4 审计**（小时级、CPU、零风险）：把内参/顺序/手性/耗时断言跑通并写进报告。它不涨分，但能防止后面所有实验被一个坐标 bug 废掉。
2. **A1 连通性 + 覆盖选图，B=0 三例**（一次 ReSplat 推理 × 策略数）：这是 R 第一优先级、也是我们唯一「未真正验证」的高杠杆项。
3. **把 B2/B1 的已测结论补成归档 JSON**（campaign N 只留下了一条 `train_record.json`，没有 `summary.json`）：锐化 + 匹配 LR + λ_dssim 0.6 的三例统一口径重跑一次。**在它进归档之前，所有 B 侧结论都停在叙述层，不能作为交付依据。**
4. **A3 的只诊断版**（hw 重投影筛查 + 位姿质量指标，不训练）：决定 hw 值不值得投 A 侧预算。
5. **B3 锚定 / B4 深度项**：只有前 4 项做完、且 A 侧选图无效时才动。
6. **不做**：campaign M（等 E2E 口径定）、生成式增强、任何训练型方法。
